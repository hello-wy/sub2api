# 人民币经营账

入口：管理后台「使用记录 → 经营分析」。新接口位于
`/api/v1/admin/business/*`，旧 `/admin/dashboard/business-*` 只保留估算查询。
新页面的经营利润指**已纳入台账范围内的经营利润**。

## 启用与期初

1. 正常启动后端，迁移器执行 `252_business_ledger.sql`。迁移执行时间为启用日；
   原有余额和未到期订阅生成未知来源期初事件，不自动视为真实收款。
2. 在「核对与配置」建立供应商成本池，绑定账号，登记生效时间及上游价格。
   同一供应商余额可以绑定多个账号。账号月租另录费用，可与按量成本并存。
3. 在待核对列表补录余额的付费额度、赠送额度、未知额度及付费人民币价值；
   三种额度之和须等于期初总额度。冻结余额保留在组成中。
4. 未到期订阅填写启用日以后剩余服务期对应的人民币价值及赠送资金比例。
   不能用整张历史月卡价格填作剩余价值。
5. 登记剩余上游采购额度及人民币价值；预付月租等填写剩余服务期，并勾选
   「期初预付费用剩余价值」，避免重复计入现金支出。

迁移不根据今日充值比例或美元汇率猜测历史人民币收入。来源未知的期初余额
在消费时仍产生收入缺口；启用前的区间始终显示历史缺口。历史积分单位沿用
已有迁移后的站内额度，不再重复换算。

## 日常登记

- 线上收款与退款由支付状态变更捕获，使用支付和退款实际发生时间。余额购买
  订阅属于内部价值转移，不增加现金收款。
- 线下收款可仅登记凭据，也可同时给指定用户充值。补登已完成充值的款项时，
  不要勾选再次增加余额，并在待核对列表补录原余额变动来源。
- 上游预充值登记采购人民币金额和到账额度，按剩余采购价值移动加权结转。
  新增生效价格版本不改写调用已保存的价格快照。
- 后付费成本先按合同暂估。月底选择「按供应商完整账单核对」，录入完整金额
  和期间，系统保留覆盖明细并记录差额。实际支付时另记「仅现金付款」费用。
  重叠期间不能重复核对；更正账单先冲销原核对记录。
- 账号租赁填写服务起止时间；服务器、域名、人工等可按期间或一次性记费。
  账号提前停用使用「提前终止」，剩余预付费用在终止日结转损失。
- 采购退款、失效分别登记。现金奖励、实物奖品、佣金填写实际支出，不填写
  站内奖励面值作为现金成本。
- CSV 导入提供模板及逐行校验、重试结果。批量收款不直接增加用户余额。
  幂等键代表同一凭据，不应在不同业务中复用。

## 收入、成本与可信状态

余额消费按消费时付费、赠送、未知组成分配。付费部分保留实际收款价值，
未知部分显示缺口。例：100 元购 100 额度、80 元购 100 额度，再赠送 100，
消费 30 时确认收入 18 元；若上游成本 6 元，赠送兑现成本为其中的 2 元。

日卡、月卡按每笔独立订阅期摊销。重购保留旧期并在权益终止时结转余额。
模型收入按该订阅当日扣减额度分摊；无用量的服务期收入保留「未使用订阅」
归属。套餐、分组、账号及模型可钻取至原始凭据。

账号固定费用按当日上游标准计价用量分摊，零用量保留闲置成本；公共费用
保留全站。赠送兑现成本是总服务成本的切片，不再次扣减；会员优惠是实收
减少的说明项，不作为第二笔费用。

金额通过十进制字符串传输，人民币计算及入账保留 8 位小数，上游价格保留
10 位；仅显示时保留两位。原币、汇率和人民币结算额独立保存。
报表采用站点报表时区；录入控件明确标注本机时区后转换为带时区时间。

利润缺关键数据或存在暂估时，最终利润字段为 null，页面显示「利润待核对」，
同时显示已知收入与成本差额。账单核对后的覆盖成本被修订时也重新待核对。
未知成本明细使用 null，不伪装成零成本。
余额、待确认价值卡片显示最近入账时点；它们不是历史所选区间期末余额。

## 事务、重放与追溯

经营事件与原业务变更同事务写入。正式 API 扣费在余额事务内写金融快照，
失败则整笔回滚；用量日志触发器用于补充未走该路径的使用证据。同一请求
通过来源唯一键去重，冻结、释放和结算通过批次身份保存资金组成。

后台每 15 秒增量入账，事务级处理事件。以未处理事件集合读取，不依赖序列
ID 的提交顺序；补录、冲销和采购修订会重放派生账目并增加报表修订号。
原始事件、价格版本和绑定版本不可更新或删除。清理 usage_logs 不影响凭据。
汇总、台账、配置和待核对列表使用独立请求，汇总失败时仍可录入台账。

上游实际扣费、供应商账单差额必须有凭据。无法定位到请求的费用保留未归属；
系统无法推断未登记的真实付款，也无法自动发现所有供应商收费的失败重试。
这类费用通过账单核对或经营费用补录，不宣称已覆盖台账之外的利润。

当前区间最长 366 天，收入成本明细按区间读取并在服务端生成日汇总与分摊，
前端分批展示明细。大站点上线前应以真实数据量测量汇总及全量重放耗时；
尚未采用物化日汇总或服务端钻取分页。

## 验证

测试 DSN 必须指向可创建临时数据库的**隔离 PostgreSQL**。测试自行新建数据库、
执行完整迁移、结束后删除该数据库，不应使用生产 DSN。

```sh
GOMAXPROCS=2 \
BUSINESS_LEDGER_TEST_DSN='postgres://user:password@127.0.0.1:5432/postgres?sslmode=disable' \
go -C backend test -p 1 -tags=unit \
  ./internal/service ./internal/repository ./internal/handler/admin \
  ./internal/server/routes ./cmd/server \
  -run 'Test(BusinessLedger|ExecuteRefund|FinishRefund|FinalizePendingRefund|QueryAndFinalizeRefund|UsageBilling|DeductUsageBilling|ApplyUsageBilling|ReserveUsageBilling|CaptureUsageBilling|ReleaseUsageBilling|ProvideCleanup)' \
  -count=1 -timeout=4m

pnpm --dir frontend exec vitest run \
  src/components/admin/usage/__tests__/BusinessAnalyticsPanel.spec.ts \
  src/components/admin/usage/__tests__/BusinessRecordDialog.spec.ts \
  src/components/admin/usage/__tests__/BusinessLedgerCSV.spec.ts
pnpm --dir frontend run build
```

GitHub Actions integration 作业已配置独立 PostgreSQL 服务；上述前端测试已纳入
根 Makefile 的关键回归集合。本地验证不代表已执行生产迁移或完成部署。
